# E-com

Магазин на React + TypeScript. **Фронтенд-частина** проекту (бек пише окрема людина).

```
e-com/
├─ frontend/   Vite + React + TS + Tailwind v4 (стан через хуки, без стору)
└─ backend/    порожньо — місце під бек товариша (див. backend/README.md)
```

## Запуск

```bash
cd frontend && npm install && npm run dev
```

Відкрити http://localhost:5173

## Дані без беку (моки)

Поки беку немає, фронт працює на моках — `frontend/src/api/mock/`:

- товари — `mockProducts.ts` (картинки лежать у `frontend/public/images`)
- замовлення — `mockOrderStore.ts` (зберігаються в localStorage, тож історія в кабінеті теж працює)

Перемикач — `frontend/src/api/config.ts`: якщо в `.env` є `VITE_API_URL`, фронт
ходить на реальний бек; якщо ні — на моки.

## Підключення реального беку

1. Товариш реалізує API за контрактом із `backend/README.md`.
2. У `frontend/.env` вписати `VITE_API_URL=<адреса>`.
3. Готово — код фронта міняти не треба.

## Що вже є

- Хедер (лого, навігація, кабінет, кошик з лічильником) + мобільне меню
- Каталог товарів
- Кошик як висувна панель + оформлення замовлення
- Особистий кабінет — історія замовлень
- Футер у стилі e-commerce

## Ключові рішення

- **Стан через хуки.** Кошик — `CartContext` + `useCart`, дані в localStorage.
  Товари/замовлення — хуки `useProducts` / `useOrders`. Жодного Redux/Zustand.
- **Дизайн-токени в одному місці** — `frontend/src/index.css` (`@theme`).
- **API-шар ізольований** — `frontend/src/api/`. Заміна моків на бек = один прапорець.
